# Integration API

Import from vision_tables. Public CLI accepts --state-dir (or VT_STATE_DIR) for every invocation. The application uses settings.state_dir for runtime assets, immutable sources, per-job artifact roots, and SQLite. --output chooses published exports. The coordinator owns pyproject, uv.lock, schemas, config, contracts, models.py and pipeline.py. Propose dependency or contract additions to the coordinator.

- vision.inspect_source(path: Path, artifact_root: Path, settings: Settings) -> Ingested. Caller has allocated artifact_root (unique, below state_dir/jobs). Inspect bytes, enforce bounds and copy input, produce source.original_path, Page.image_path and further artifacts as paths relative to artifact_root. Explicit media detection, overwrite prevention, geometry/quality/text checks. Skips include pages dropped by budget. Ingestion never infers semantic relationships. Runtime code also under vision or runtime*.py may be split as desired.
- vision.read_page(page: Page, regions: list[Region], artifact_root: Path, settings: Settings) -> PageReading. Runtime owns caller bounds, status/attempt artifacts, process-shared lock and grouping local fields. This includes native PDF inputs. Preserve evidence text and exact region relationships where grounded, abstain when uncertain. Model process can run under state_dir/direct-env/bin/python with local model at state_dir/models/qwen; new runtime uses models.runtime_info(settings) for capabilities. Propose additional names through coordinator. Hybrid requires the full parser PLUS Qwen. Use a prompt small enough for the real model to finish, and an explicit overflow signal. Model paths are config, never supplied by document content.
- domain.assemble(ingested: Ingested, readings: list[PageReading], scope: list[int], run: Run, document_id: str) -> Document. Inputs filtered to document scope. Assemble evidence graph and issues. Domain owns controlled field vocabulary (publish it for vision), decimal/range/quantity and date parsing, validation, parent joins and review reasons. Repeated rows remain distinct; scope can include skipped pages. Processing errors with no useful data must surface. domain.revalidate(document: Document) -> Document recalculates derived observations and domain issues after correction. domain.apply_corrections(document: Document, changes: CorrectionSet) -> Document enforces typed changes, recomputes, preserves old version, increments version and checks review policy. Reasoner audit informs final contract.
- pipeline.extract(path: Path, output: Path, settings: Settings, *, job_id: str | None = None) -> list[Document]. Writes originals, inspect/read files in settings.state_dir/jobs/<job_id>, and job status in that artifact root; output reserved for caller's export destination. Returns fresh candidates with version=1. Persistence assigns durable version/parent for reprocessing under same document ID. CLI owns starting/recovering SQLite job states, applying the returned list transactionally and publishing exports. Expose a programmatic processing+persist+export function in storage/CLI for evaluation if needed. CLI prints recoverable artifact_root, document_id(s), version(s), status and export paths. Each review bundle resolves artifact paths to the correct durable job. Source SHA and logical page scope form document identity, effective settings/runtime form revision identity; duplicate imports may incur inference but must reuse durable canonical version and preserve human edits.
- models.runtime_info(settings: Settings) -> dict contains model, revision, versions, components and ready fields; models.doctor(settings) -> dict; models.prepare(settings) -> dict provisions pinned components (network only here). Missing runtime is ProcessingError(code, message). Hybrid supports an explicit blocked state. External service endpoints must be loopback. File-backed flock is owned by vision at calls that use local models.
- evaluate.run(manifest: Path, output: Path, settings: Settings) -> dict. QA owns schema for vetted fixtures, metric definitions, denominators and assessment limitations. Persist a machine-readable report and return it.
- Store migration 001 is reserved for initial jobs/documents/versions/entities/observations/corrections. Add new migrations sequentially through coordinator. Package migrations or embed SQL where installation can find it. SQLite uses parameterized operations, serialized version allocation, unique source/config/doc, immutable snapshots. A batch that resumes uses canonical rows and completed outputs, handles expired job ownership without clobbering concurrent work. Version-specific export publication must be atomic. CLI and persistence specialist owns these implementation files.

All agreements and status are local to this repository. Hand off committed changes via SHA and the Orca coordinator mailbox.
