## Independently checked fixes and evidence

**Migration 003 — passed on the exercised upgrade.** The SQL and checksums for store migrations 001 and 002 match the actual Opus-reviewed code. The QA test rebuilt an 002 database with three historical snapshots, including reused crop IDs with different transforms. The upgrade recovered severity and transform for the correct document/version, defaulted a missing historical severity to `review`, preserved snapshot bytes and hashes, rejected update/delete attempts, and reopened idempotently. A separate injected SQL failure after the first backfill restored the 002 schema and triggers. A clean retry applied only 003.

**Single-snapshot lineage and review-page visibility — passed on the reproduced cases.** The QA tests now check `PRAGMA foreign_key_check` and assert exactly one full snapshot in extracted and corrected standalone files. I also created v2 under changed configuration and then corrected v1 to v3. The v3 file contained full snapshot 3, lineage rows 1 and 3 with their original hashes, and correction (1,3). The sibling v2 was excluded and all FKs resolved. The boxless mixed-style summary is present in `review.json.page_styles` with its page reference. Page-only field citations still have no region. A grounded native PDF line kept its printed style. French language hints left the ambiguous numeric date and dollar currency unresolved. Parser block boxes and crop extents carry distinct precision. Finding 2 concerns how those extents are used for a relationship.

**Native Paddle feasibility — passed for one synthetic page.** Hashes of the 700 × 480 image, parser JSON and Markdown match the committed artifacts and both original pass directories. PP-DocLayoutV3 and PaddleOCR-VL-1.6 ran on CPU, yielding six detector boxes and four recognized blocks. The full-parser log confirms 10.036 s initialization, 15.838 s for the first prediction and 15.705 s for the second with the model resident. One run per condition, one process, 46.04 s wall time and 10,105,159,680 bytes process peak RSS. These are parser-only measurements. The separate real 32-token run recorded four crop sequences of 7, 32, 32 and 12 tokens. Crops 2 and 3 hit the cap without EOS. The committed budget receipt matches the original receipt byte for byte, and the production telemetry validator returned two cap hits with complete telemetry. The original per-crop sequence statistics and four block rectangles match the summary. The current parser environment reports all 100 locked package versions. No new inference was needed.

**Archive split — passed for manifest integrity and scoped references.** The production manifest loader verified seven image/label SHA-256 pairs. IDs, families and source hashes are disjoint across both manifests. The development split has Babani (1 labeled field), Le Versailles (3) and Jefferson (4). The held-out split has Carter (2), Delmonico’s (8), Bedingfield (6) and Lutz-Messmer (6). All seven provide attribution, rights and a human catalogue or transcription source. Both held-out recipe crops match the referenced parent scans pixel for pixel under the recorded affine. The labels were committed before the recorded Paddle run and while direct inference was pending. Their scope is eight development fields and 22 held-out fields, including three null labels in total. No family is labeled exhaustively and no case is eligible for automatic acceptance. These data cannot establish whole-document recall, calibration or contemporary commercial accuracy.
