# Gate 2 independent contract audit

**Freeze verdict at `e55f50e` — failed.** The proposed wire types admit silent changes to readings and approval without a human decision. Using the exact draft and pinned Pydantic, a repeated JSON key changed a reading from `8.50` to `6.50`, a correction value of `1` became `True`, and an invoice with zero observations validated as `human_approved`. These results concern the contract boundary. The runtime, correction command and store were not present at this revision. The independent audit is complete.

Scope includes the [project request](REQUEST.md), [prose proposal](contracts.md) and [integration API](interfaces.md), plus the typed contracts and settings committed on main. The existing API split is usable. Keep the source digest, one-based original page numbers, explicit page grouping in source order, bounded retries, top-left page affine, page/region consistency checks, distinct observation and entity IDs, cycle checks, and default `needs_review`. The [audit evidence](../../evidence/development/reasoner.md) contains the executed probes and their limits.

## A. Model output, trusted runtime metadata and parsing

**Blocker.** `PageReading` in `contracts.py:108` combines model readings with regions, coordinates, issues, completeness flags and free-form call dictionaries. `FieldRead()` defaults to a readable empty field. The API calls for bounded parsing and an overflow signal but leaves the model payload and authoritative finish conditions unspecified. `Wire` forbids extra keys while still allowing type coercion. Independent validators that receive an already-decoded dictionary cannot recover a duplicate key.

**Freeze change.** Publish a small model-facing schema for ordered records with allowed kinds, parent links, field names, source text, state, alternatives and optional references from a supplied region/crop inventory. Require the semantic fields explicitly. The adapter supplies page identity, trusted layout geometry, call IDs, component/revision, input artifact refs, token limit/usage if available, finish reason, attempt outcome and whether it used constrained generation. Reject unsupplied refs. Parse exactly one bounded JSON object, checking duplicate keys at every level before constructing a dictionary. Reject trailing content, nonfinite numbers, wrong types, excess size/depth and invalid domain vocabulary. Apply the strict wire and semantic validators on every path, including constrained output and correction files. If supporting a wrapper, document the one lossless transformation. Persist bounded local raw attempts, parse failures and exhaustion. A retry consumes the same documented call/crop budget. Formatting repair cannot supply missing rows, force a reading, or resolve disagreement.

**Acceptance.** A duplicate amount, concatenated objects and a numeric boolean each fail with an attributable error. A fully valid object accompanied by a token-limit stop is incomplete even if its last character is `}`. Contradictory readable attempts survive as alternatives with an issue. A direct response supplying a box, call metadata or approval is rejected. A matching supplied region can be referenced. Exhaustion and a blocked hybrid route return explicit statuses. Record fixed maximum calls per page including rereads and shared-lock usage for both routes and evaluation. `Settings.inference_lock` currently defaults per state directory in `config.py:52` — concurrent calls from two isolated worktrees must contend on one project-owned lock.

## B. Coverage, validation and approval

**Blocker.** `Document.references` at `contracts.py:232` accepts a page that is both skipped and incomplete and carries an observed amount. It accepts `original_capture="suspected_incomplete"` with the other capture flag false, zero issues and human approval. A source page excluded before scope construction disappears from the document-level denominator. `validation="incomplete"` also prevents reporting arithmetic validation independently of capture.

**Freeze change.** Inspect the source once and persist the source count, requested groups and a job-level disposition for every known original page. Build document identity from intended scope before budgets. Account explicitly for pages outside selected groups. Reject out-of-range groups and apply a documented default for ungrouped/mixed pages. For each requested page record one result such as read, partial, skipped or failed, with reason, attempt/artifact refs and tested limits. Keep rendered pages distinct from read pages. Report unknown page count as an inspection failure when inspection cannot determine it. Separate processing extent, capture assessment, domain validation and reviewer decision. Use one capture field, default `not_established`. Suspected cutoff creates a review issue, detected omissions or truncated calls make processing incomplete. Permit retained partial observations to carry page evidence. Scope a `not_present` finding to inspected content. An unassessed field on a failed page must never turn into an observed absence.

**Acceptance.** For a three-page PDF grouped [1,2,3] and limited to two pages, retain the three-page scope, identify page 3 as skipped with reason, and report 2/3 read. A partial page with a total mismatch exposes both conditions. For explicit group [2], identify 1 and 3 as outside selection in the job. A clean full-frame photo still has capture `not_established`. A photo with a cut-off last row produces a localized issue. All pages failed, an empty recognized document, and an unrecognized document each yield an explicit terminal/review outcome and cannot qualify as a successful approved extraction.

## C. Grounding and field states

**Blocker.** `Evidence` carries page, optional region and quote. Two targeted crops from the same page are indistinguishable unless ingest/runtime persists their identity and mapping. `Observation.reading` accepts a readable observed field with raw and value both null and an empty quote, and an ambiguous observation without alternatives or a reason. A reference to a real region alone cannot establish that its text supports a claimed reading.

**Freeze change.** Bind evidence to the immutable job/source, page and optionally a trusted region or crop artifact. Include an attempt/channel reference (native text, parser or direct vision) so a reviewer can inspect each candidate. Use a versioned coordinate convention for raster orientation, PDF crop box/rotation/user unit, pixel edges, dimensions and transforms from each crop/render to original page space. Retain the source artifact digest and effective transform. Map all four corners, check bounds and record box precision. A page-only citation is valid for direct vision. A crop box describes the crop extent. Limit region/field boxes to their actual grounding. For overlapping native/visual text retain both evidence channels without double-counting the row or silently choosing conflicting readings.

Require a raw reading and evidence text/reference for readable observed fields. Distinguish readable raw text with unresolved interpretation (e.g. an ambiguous date or currency) from an absent observation. Preserve the raw text, alternatives with their evidence when known, null unresolved normalized values, and a reason when there is ambiguity or no defensible candidate. Keep attempts, human edits and calculations independently attributable. Decode artifact references only through the job's artifact catalog under its resolved root. Use process-generated job IDs, safe paths and parameterized storage. Document content remains inert through inference, export and review.

**Acceptance.** Reopen a review bundle from a new output directory and locate two distinct crops on a rotated page. With crop-to-original `x=5+v/2, y=195-u/2`, the square [0,0,10,10] covers [5,190,10,195] in original units. Reject a supplied region from another page or a box outside the original. Native plus raster observations of one printed line produce one entity; two identical physical rows produce two. A direct reading without coordinates still names the page and original text. A misread digit and its reread can be inspected separately.

## D. Identity, durable versions and publication

**Blocker.** `interfaces.md` names a unique source/config/document combination and also requires immutable corrected versions. Putting that unique key on every version prevents corrections under the same config. `Settings.content_settings()` contains settings only, while `Run.config_hash` accepts any digest. The draft leaves content-affecting dependencies, retries of failed attempts, and the target returned on reimport to separate implementers. `Document(version=2,parent_version=3)` validates.

**Freeze change.** Define the logical ID with a tagged canonical UTF-8 serialization of source byte SHA-256 and validated ordered scope. Distinguish job/attempt UUID, logical document ID, extraction key and immutable snapshot key `(document_id, version)`. Publish one fingerprint function over effective model/component revisions, route, schema, pipeline/normalizer/prompt revisions, content-affecting runtime/decoding options and budgets. Exclude output, state/lock paths, volatile measurements and job ID. Attach path-based evidence to the durable originating job. Keep the extraction key unique on a base-extraction mapping, with corrected snapshots keyed separately. Record failed/incomplete attempts and define which states allow recovery or reuse. On import of an existing base, return the appropriate reviewed descendant for that base or explicitly reference it, preserving later edits. A changed extraction produces a new review candidate; link its lineage and preserve the historical approved snapshot. Similar photos create separate document IDs and a possible-duplicate review link.

**Acceptance.** Same bytes/config in two directories and from two simultaneous jobs resolve to one base. Reimport after correction preserves the edit and its evidence. A new component revision or render budget yields a distinct extraction key under the same logical ID. Regrouping pages changes the document ID. A failed attempt followed by a successful retry can publish the good result. Reject missing, self, forward or foreign parent versions. Pin all exports to one snapshot key. Simulate an interruption before DB commit and after commit before export publication. Readers see a complete published version or a recoverable pending export. Retry publishes JSON, relational CSV and SQLite with matching IDs, order, status and values. Formula-active text is escaped only in the CSV presentation.

## E. Correction replay and human decisions

**Blocker.** `CorrectionSet` at `contracts.py:192` requires at least one field edit, so approving a correct document requires fabricating a change. It accepts two changes to one target, has no explicit replay identity, and can carry conflicting state/value combinations. The document model permits approval without any reviewer event. A free-text `Derivation.calculation` plus a list of input IDs describes lineage but does not specify deterministic recalculation.

**Freeze change.** Accept either actual typed changes or an explicit review decision. Require reviewer, base document/version, action and reason where applicable. Have the store record time, a unique operation ID or canonical event digest and committed child version. Check same operation/payload first for an idempotent response, then compare-and-swap the expected base/head in one transaction. Reject stale or foreign bases, unknown or repeated targets, reuse of an ID with a different payload, and direct edits to computed fields. Validate current field type/state and whole graph. Keep the original observation and evidence available from an immutable baseline, append a human-supplied overlay with a stable target, rederive all dependent observations in dependency order with a versioned formula and rounding rule, and rerun validation. Preserve capture evidence and unresolved issues. Serialize normalized results and a stable row order for replay. Version changes reset approval unless an explicit successful reviewer decision applies to that exact result.

**Acceptance.** Start with printed 2 boxes × 6 bottles × 1 L and a displayed 12 L. Correct 6 to 5. Derived volume becomes 10 L, the displayed 12 L and all three original inputs remain inspectable, and a discrepancy is visible. Replay the stored edit offline on the same base with pinned rules and recover the same facts/issues. A simultaneous different edit on that base conflicts. Retrying the committed edit returns its original version. An invalid batch applies zero edits. Approve an unchanged valid document without editing any field. Require an attributable human decision, resolved type-specific blockers and adequate processing coverage for approval. A newly parsed, arithmetically correct invoice still starts in review.

For manual approval, publish the per-type blocking issue codes and how a reviewer resolves them. Examples are an unresolved critical amount or total mismatch for an invoice, a detached price for a menu, and a conflicting ingredient digit for a recipe. A documented missing optional yield can remain visible on an otherwise faithfully transcribed recipe. Record severity and resolution so historical or informational issues can remain in the review bundle after a reviewer resolves a blocker. The current `Document` approval guard treats every issue alike.

## F. Domain vocabulary, entity relations and exact values

**Blocker.** `RecordRead.fields` and `Observation.field` accept any identifier. The draft accepts two effective values for the same entity/field and allows a string such as `"NaN"` on an unknown field. `DocType` has four broad routing families. `Entity.parent_id` supports containment but does not name the relationship between a bundle choice and a reusable menu item. Runtime and domain need the same versioned dictionary before independent implementation.

**Freeze change.** Publish allowed kinds, subtypes, fields, normalized lexical types, cardinalities, allowed parent/relationship endpoints and critical fields per type. Family `invoice` can remain the route if subtype explicitly distinguishes invoice, credit note, receipt, delivery note, quote and unknown. Model local IDs are page/attempt scoped. Assembly issues stable occurrence IDs, preserves ordinal and table column/row relationships, and links continuation only on documented evidence. Distinguish repeated observations/candidates from a single effective field. Model relationships as typed edges or named link entities with validated endpoints, order and evidence. Export the same relations in CSV and SQLite. Keep finite, bounded Decimal strings for exact decimal fields, strict booleans for flags and null for unresolved values. Preserve source language at reading/region level independently of locale. Represent ranges, qualifiers, explicit units and exact fractions in named fields or typed values instead of overloading a generic value string.
